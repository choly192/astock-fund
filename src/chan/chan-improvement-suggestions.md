# 缠论算法改进建议

> 适用版本：评估基线为算法 1.0.4（`src/chan/engine.ts`）
> 范围：`src/chan/engine.ts`、`src/chan/validation.ts`、`src/webview/chanSignalSeries.ts`、`src/chan/seriesData.ts`
> 说明：本文仅记录问题与改进方向，不包含代码修改。

> 实施状态（算法 1.0.5）：已完成规则命中与展示事件分离、市场状态函数复用、回撤口径修正、资产成本与卖点语义标注、覆盖率敏感性报告。3.1、3.2、3.4 等会改变信号的建议仍作为独立实验候选，未直接进入生产规则。

## 1. 算法流水线概览

当前实现是一条单级别流水线：

1. **K 线包含处理** `mergeIncludedBars`（engine.ts:99）—— 向上取高高、向下取低低
2. **分型识别** `detectChanFractals`（engine.ts:151）—— 合并 K 线上的顶/底分型，用第 index+2 根做"稳定器"确认
3. **笔构建** `buildChanStrokes`（engine.ts:202）—— 相邻异型分型连笔，间距约束 ≥3
4. **线段构建** `buildChanSegments`（engine.ts:222）—— 笔端点上的简化转折
5. **中枢识别** `findChanCenters`（engine.ts:266）—— 连续三笔重叠成中枢，终点在区间内则延伸
6. **信号识别** `detectChanSignals`（engine.ts:475）—— 标准一/二/三类买卖点 + 周线专属的局部背驰一买（local-divergence）、独立二买（local-second）

## 2. 现状中值得保留的设计

- **防未来函数工程扎实**：`replayChanAnalysis`（validation.ts:336）逐 K 切片回放，检测 `future-confirmation` / `missing` / `mutated` 三类稳定性违规；信号时间与确认时间分离（`firstConfirmedIndex`），回测从下一根 K 线开盘价成交（validation.ts:469）。
- **开发/留出时间切分**严谨，跨越切分点的持仓不进入任一侧（validation.ts:476-479），留出集保留历史做结构预热。
- 数据校验严格：OHLC 一致性、时间严格递增、价格为正（validation.ts:223-262）。
- 分型确认时间在合并 K 线延伸时保持固定，并有专门测试守护（chanAnalysis.test.ts:58）。
- `chan.md` 如实记录外部审计结论（仅周线局部信号通过、明确不作为自动交易依据），克制态度值得保持。

## 3. 算法语义问题

### 3.1 一类点在"第一笔离开"时的力度比较对象不符合背驰定义（高）

`detectChanSignals` 中 `index - center.endStrokeIndex > 3` 才跳过（engine.ts:496），即允许离开笔相对中枢末端偏移 1、2、3 根：

- 偏移 3（`index = e+3`）：`strokes[index-2]` 恰好是第一离开笔（e+1），构成标准趋势背驰比较。
- 偏移 1（`index = e+1`）：`strokes[index-2]` 是**中枢内部的同向笔**，用它和离开笔比力度，既不是趋势背驰，也不是标准盘整背驰（盘整背驰应与**进入中枢的那段**，即中枢首笔的前一笔比较）。

这会在"第一笔刺穿中枢边界就出现斜率衰减"时产生一类信号，语义偏宽松。

**建议**：收紧为只在第二离开笔（偏移 3）判定趋势背驰；若要保留盘整背驰，显式新增 variant，并以进入中枢段作为力度比较对象。

**实证结论（2026-08，见 §8）**：偏移 1 信号在留出集 h10/h20 均为明确负贡献（PF 0.63 / 0.51）；偏移 2 中性偏正（PF 2.01 / 1.04）；偏移 3 长持有期有效（h20 PF 1.13）、短持有期样本内偏差。落地建议是**剔除偏移 1、保留偏移 2/3**（dropOffset1 变体），而非一刀切收紧为仅偏移 3。

### 3.2 中枢延伸与三类点回抽只看笔终点，忽略影线刺入（高）

> 复核修正：当前 `ChanStroke.low/high` 只由两个分型端点构成，向下回抽笔的 `low` 与 `end.price` 等价，直接替换三买条件不会改变结果。要识别笔内影线，必须先保存对应原始 K 线路径的真实最高/最低价；中枢改用整笔重叠会显著改变中枢数量，应作为独立实验而非直接修复。

- 中枢延伸条件（engine.ts:279-281）只判断 `stroke.end.price` 是否落在 [low, high] 内。一笔终点在区外、但途中已与中枢重叠（或终点在区内、笔身从未重叠）的情况都未按缠论处理。按定义，笔与中枢区间**有重叠**（`stroke.low <= center.high && stroke.high >= center.low`）即应视为接触。
- 三买判断 `retest.end.price > center.high`（engine.ts:554、565）只要求终点站回上沿外，回抽笔的**最低点可能已经刺入中枢**——这在缠论中属于假三买。改用整笔不进入中枢（如 `retest.low > center.high`）更严格。

**建议**：两处统一改为区间重叠/整笔不越界判定。改动会影响信号数量，必须用现有回放框架做开发/留出对照回测。

**实证结论（2026-08，见 §8）**：回抽笔影线刺入中枢的三类点为负贡献（h10 PF 0.73、h20 PF 0.76），整笔不入中枢的显著更优（h10 PF 1.53）；严格化后三类卖 h10 平均 +3.90%、PF 4.68。但中枢延伸若直接改为重叠判定会过度合并——实验中三类点 845→0、一类点 454→73，不能作为直接替换，需同步重调离开/进入判定。

### 3.3 线段算法过度简化，且计算结果无消费者（中）

`buildChanSegments`（engine.ts:222）只在笔端点上做三值转折 + 同类取极值，没有特征序列包含处理，也没有线段破坏的分型确认，复杂震荡中会频繁错分。同时全仓库检索确认 **segments 没有任何下游消费者**——信号不使用、webview 不绘制。

**建议**：二选一：

- 补全特征序列逻辑，并将线段用于更高级别结构（中枢扩展/新生、线段级背驰）；
- 或直接移除，减少维护负担。

### 3.4 背驰力度定义单薄，已有数据未利用（中）

- 力度 = `振幅 / 跨度`（engine.ts:295），只是价格斜率代理。缠论背驰的核心动能证据——**MACD 红绿柱面积、黄白线回拉零轴**——未实现。
- 包含处理时累加的 `volume`（engine.ts:136）在力度判断中完全没有使用。
- 横盘后缓慢创新低很容易满足斜率衰减；`meaningfulAmplitude`（0.5 阈值，engine.ts:300）只部分缓解。
- `MAX_DIVERGENCE_STRENGTH_RATIO = 0.85`、`MIN_DIVERGENCE_AMPLITUDE_RATIO = 0.5`（engine.ts:299-300）为硬编码魔数。

**建议**：引入 MACD 面积（及可选成交量）作为力度主判据，价格斜率降为辅助；阈值参数化并纳入回测扫描。

### 3.5 两套并行的结构识别逻辑，关联脆弱（中）

> 算法 1.0.5 已处理统计和重复实现问题：图表继续按事件去重，验证层保留全部规则命中；市场状态计算已抽到共享模块。局部信号仍保持独立结构流水线，等待后续候选规则验证。

周线局部信号（engine.ts:397-473）在**未做包含处理的原始 K 线**上用 5 根窗口另找 pivot，与主流水线（合并 → 分型 → 笔）完全独立，`strokeIndex: -1`，两套结构之间无引用关系：

- 去重 key 为 `${time}:${side}:${level}`（engine.ts:579），**不含 variant**：时间巧合相同时局部信号与标准信号互相覆盖，variantMetrics 的统计口径会随之变化；时间不同则同图并存。
- `classifyLocalSignalRegime`（engine.ts:361）与 validation.ts 的 `classifyMarketRegime`（validation.ts:438）是重复实现，参数一处硬编码（60/20/0.005）、一处可配，调参时容易漏改。

**建议**：统一到同一条结构流水线（局部信号改为消费笔/中枢结构），或至少让去重 key 包含 variant、 regime 分类函数复用同一实现。

### 3.6 信号无失效机制（中）

图上所有历史信号永久绘制。例如二买之后价格继续跌破一买低点，该二买实际已失败，但图上仍显示买入标记。

**建议**：为信号引入状态（active / invalidated），如二买失效条件 = 收盘跌破一买价格；失效后在图上灰显或打叉，回测中也可统计信号存活率。

### 3.7 单级别、无递归联立（低，功能完整性）

没有中枢扩展/新生的级别递推，也没有多级别联立（如日线笔对应 60 分钟线段），三类点之后的中枢移动与趋势延续判断缺失。这属于功能边界而非缺陷，但限制了信号质量上限，建议在 3.1/3.2/3.4 验证有效后再评估投入。

## 4. 回测方法学问题

### 4.1 maxDrawdown 计算口径有误导性（高）

> 复核修正：旧实现会混合标的和日线/周线，但 `summarizeTrades` 已先按 `horizon` 过滤，并不会混合 5/10/20 持有期。报告 1.3.0 已改为明确命名的信号序列回撤，并补充按标的计算的中位数和最差值。

`summarizeTrades`（validation.ts:568-575）把**跨标的、跨周期、跨持有期（5/10/20 混合）**的交易按时间排序后连乘成一条权益曲线：

- 重叠持仓复利连乘没有真实组合对应；
- 跨标的连乘会人为制造回撤。

**建议**：按 (symbol, period) 分别计算回撤后再聚合（如取平均或中位数），或在报告中明确标注该指标仅为"信号串行复利基准"。

**实证结论（2026-08，见 §8）**：现口径下 h10 回撤 98.91%、h20 100.00%；按 (symbol, period) 分组串行后平均回撤仅 15.04%（最差单组 95.46%，68 组）。报告中的近 100% 回撤确为跨标的连乘伪影，建议立即修正口径后重跑历史报告。

### 4.2 机会覆盖率的参数敏感性未报告（中）

> 报告 1.3.0 已增加涨幅阈值上下 3% 与信号窗口上下 3 根的九组敏感性结果。

29.8% 的覆盖率（见 chan.md）依赖硬编码的 cooldown=10、信号窗口=8、涨幅阈值 15%/12%（validation.ts:626-632）。这些参数小幅变动就可能显著改变覆盖率。

**建议**：报告增加敏感性小节（如阈值 ±3%、窗口 ±3 根下的覆盖率区间），避免单点数字被过度解读。

### 4.3 成本模型对股票偏乐观（中）

> 报告 1.3.0 已增加资产类型和默认 5bps 股票卖出印花税；卖点收益明确标记为不可执行裸空的下跌跟随指标，不再扣除虚构的做空交易成本。

`feeBps=3` 单边（validation.ts:184）未含印花税（卖出约 5bps），对 ETF/基金尚可，对股票偏乐观。参数可调但默认值影响所有报告结论。

**建议**：按标的类型设置默认成本，或在报告中同时给出含/不含印花税两档结果。另外 sell 侧收益等价于做空（validation.ts:406），A 股不可裸空，`all` 汇总混合多空时需在文档中提示。

### 4.4 其他统计细节（低）

- `netReturn === 0` 的平局既不计 win 也不计 loss，但胜率分母含平局（validation.ts:564-584），样本小时胜率口径需留意。
- 回放为 O(n²) 全量重算（validation.ts:363）；单次分析内对每笔都 `[...centers].reverse().find(...)`（engine.ts:490）为 O(n × centers)。日线 1500 根 × 逐 K 回放离线可接受但偏慢，center 查找可改为游标或二分。

## 5. 工程健壮性问题

- **非空断言** `guardStrokeConfirmation(guard)!`（engine.ts:507、518、537、557、569）目前靠循环边界隐式保证安全，重构时容易踩空。建议让 undefined 显式跳过。
- **局部信号数组访问无防御**：`points[confirmedIndex]`（engine.ts:443、466）当前靠 pivot 循环 `index < points.length - 2` 保证不越界，属于脆弱耦合，建议显式判空。
- **结构不可视化**：中枢已经计算且是信号依据，但图表只画信号三角（chanSignalSeries.ts），不画笔/中枢/线段，用户无法从图上理解信号来源（仅有文字 reason）。建议至少叠加中枢区间矩形。
- **魔数散落**：`minimumSpan=3`、`LOCAL_REGIME_*`（engine.ts:345-347）、`UPSIDE_*`（validation.ts:626-628）等建议集中到 options 并贯穿 CLI。

## 7. 建议的推进方式

1. 先将 3.1、3.2 拆成独立候选规则，只用开发集做对照；规则冻结后必须使用新的标的或新的时间段验收，已经查看过结果的 40 标的验收集不能再次用于规则选择。任何使稳定性违规增加的修改直接否决。
2. 修正 4.1 回撤口径后重跑历史报告，确认既往结论是否变化。
3. 再评估 MACD 力度（3.4）与信号失效（3.6），两者可独立于结构改动验证。
4. 多级别联立（3.7）作为后续大版本方向，不在小版本中混入。

> **2026-08 更新**：第 1、2 步的对照实验已完成（见 §8）。实证后的推荐落地顺序为：① 4.1 回撤口径修正（零风险、立即消除误导性指标）；② 剔除一类点偏移 1（dropOffset1）；③ 三类点改整笔不入中枢（strictThird）；②+③ 合并后留出集 h10 PF 1.27 / h20 PF 1.16。重叠式中枢延伸（overlapCenters）经实证会过度合并，暂不落地，待中枢离开/进入判定同步重设计后再评估。

## 8. 真实数据实证结果（2026-08）

实验脚本：`scripts/chanExperiment.js`（可复跑：`node ./scripts/chanExperiment.js`）；原始数据 `.chan-validation/expanded-input.json`，结构化结果 `.chan-validation/experiment-report.json`（该目录已 gitignore）。

### 8.1 实验设置

- **数据**：真实行情 23 个标的（宽基/行业 ETF 与个股）× 3 周期（日线 1500 根、周线 500 根、60 分钟 1500 根）= 69 组、38,878 根 K 线。
- **方法**：逐 K 切片回放（防未来函数框架与生产一致），开发 70% / 留出 30% 时间切分；信号确认后下一根 K 线开盘价成交，持有 10 / 20 根，单边成本 3bps。
- **变体**：baseline（现网逻辑）、dropOffset1（剔除偏移 1 的一类点）、strictFirst（仅保留偏移 3）、strictThird（三类点要求回抽整笔不入中枢）、dropOffset1+strictThird、overlapCenters（中枢延伸改区间重叠）、combined（strictFirst+strictThird+overlap）。
- **安全护栏**：所有变体的稳定性违规（future-confirmation / missing / mutated）均为 **0**，变体之间的差异不含未来函数因素。

### 8.2 基线盘点

- 全量回放信号：标准一类 454、二类 243、三类 845；周线局部背驰 104、独立二买 232。
- 一类点中：**偏移 1 占 239（53%）**、偏移 2 占 100（22%）、偏移 3 占 115（25%）——过半一类点属于 §3.1 指出的语义存疑情形。
- 三类点中：**回抽影线刺入中枢的占 586（69%）**、不刺入 259（31%）——近七成三类点属于 §3.2 指出的宽松判定。
- 基线留出集整体无统计优势：h10 平均 -0.11%、PF 0.96；h20 平均 -0.14%、PF 0.96。

### 8.3 §3.1 一类点比较对象：偏移 1 确认为负贡献

留出集分桶表现（标准一类点交易）：

| 桶     | h10 n / 平均收益 / PF | h20 n / 平均收益 / PF | 结论                                 |
| ------ | --------------------- | --------------------- | ------------------------------------ |
| 偏移 1 | 75 / -1.01% / 0.63    | 71 / -2.17% / 0.51    | 明确负贡献，应剔除                   |
| 偏移 2 | 27 / +1.21% / 2.01    | 25 / +0.09% / 1.04    | 中性偏正，可保留                     |
| 偏移 3 | 27 / -1.53% / 0.49    | 26 / +0.45% / 1.13    | 长持有期符合教科书预期，短期样本偏差 |

变体层面：

- **dropOffset1**：机会覆盖率 39.5% → 32.7%；整体 h10 +0.08% / PF 1.03、h20 -0.04% / PF 0.99；其中一买 h20 由 +0.38% / PF 1.10 提升至 **+2.68% / PF 1.96**（n=68）。
- **strictFirst（仅偏移 3）**：覆盖率 29.9%；一买 h20 +3.26% / PF 2.15（n=55），但一卖样本仅 8 笔且表现差（h10 -2.80%），机会损失偏大。
- 副作用提示：二类点识别依赖近期一类点，剔除一类信号会连带减少二类信号（dropOffset1 中 L2 243→112），需在落地时一并复核二买/二卖表现。

### 8.4 §3.2 三类点影线刺入：确认为负贡献；重叠延伸中枢过度合并

留出集分桶表现（标准三类点交易）：

| 桶           | h10 n / 平均收益 / PF | h20 n / 平均收益 / PF | 结论               |
| ------------ | --------------------- | --------------------- | ------------------ |
| 影线刺入中枢 | 181 / -0.85% / 0.73   | 168 / -1.01% / 0.76   | 明确负贡献，应剔除 |
| 整笔不入中枢 | 83 / +1.16% / 1.53    | 77 / -0.29% / 0.92    | 显著更优           |

变体层面：

- **strictThird**：覆盖率 34.0%；整体 h10 +0.23% / PF 1.09、h20 +0.25% / PF 1.07。分多空看差异显著：**三卖 h10 +3.90% / PF 4.68（n=39）、h20 +1.50% / PF 1.75（n=36）**；三买仍为负（h10 -1.26% / PF 0.61、h20 -1.87% / PF 0.64）。
- **dropOffset1+strictThird（推荐组合）**：覆盖率 27.2%；整体 **h10 +0.70% / PF 1.27、h20 +0.59% / PF 1.16**，为所有保留足够样本量的变体中最优。
- **overlapCenters（中枢延伸改区间重叠）**：中枢被过度合并，三类点 845 → **0**、一类点 454 → 73，覆盖率降至 22.4%；剩余信号质量尚可（一买 h20 +2.64% / PF 1.76）但机会损失不可接受。结论：重叠判定理论上更纯，但在当前笔/中枢构造下不能直接替换终点判定，需与中枢离开/进入规则同步重设计。
- combined（strictFirst+strictThird+overlap）：仅剩 8 个一类点、0 个三类点，覆盖率 19.7%；精度虽高（h10 胜率 54.1%、PF 1.52）但无实用价值。

### 8.6 局限性与解读注意

- **市场环境偏差**：留出窗口约为 2023/2024–2026 年的弱市/震荡行情，买方信号整体吃亏、卖方信号占便宜（三买失效 / 三卖严格化后表现突出，部分来源于此）。上述结论应在牛市窗口数据上再验证后再用于实盘。
- **小样本桶**：strictFirst 一卖（n=8）、overlap 二卖（n=2）等桶样本量过小，不下定论。
- 变体信号检测为实验脚本中的平行实现（参数与 engine.ts 一致），用于效果评估；正式落地需修改 `src/chan/engine.ts`，并跑通 `src/_test/suite/chanAnalysis.test.ts` 与稳定性回放（违规数必须保持 0）。
- 所有变体均未改变成本模型、cooldown、机会窗口等回测参数，变体间对比是受控的。
